Working with an AI Agent: A PM Playbook

Treating AI as an Operating System for Executive Leverage

I treat an AI agent as an operating system for my product management work, not a text generator: it holds context, checks my reasoning, and handles the administrative load so my attention stays entirely on high-level judgment calls.

This playbook sets out the principles, workflows, and guardrails I use day to day with a coding-capable agent connected to core productivity and data tooling (calendars, documentation repositories, task trackers, and analytics databases).

Core Philosophy and Operating Principles

Six principles shape every workflow below, structured as binding rules rather than loose aspirations:

Principle Practical Application Why It Matters
Never Maintain Observable State If truth lives in a system of record (a ticket, calendar, or doc), the agent reads it directly. I never update a tracker by hand. Manual trackers drift. Keeping manual logs leads to synchronization gaps and inaccurate project status visibility.
Reduce Cognitive Load Work arrives as one next step, not a massive list to review. Focus blocks carry a concrete first action. Lists drain attention during re-entry. A single, defined first step removes mental start-up friction.
The Agent Pushes Back Standing instructions require the agent to challenge weak premises and flag scope creep before drafting anything. An agent that agrees by default accelerates flawed assumptions and bad architecture.
My Voice, Its Structure For shared docs and communications, the agent outlines, raises questions, and supplies facts. I write the prose. Stakeholders easily spot machine-generated copy. Human editorial control and strategic judgment remain strictly mine.
Human Review Boundaries Automations write strictly to private or staging surfaces. I review every output before anything is shared externally. Ensures zero unvetted statements or premature updates reach cross-functional partners.
Enterprise Access Paths Interactive sessions run through enterprise-secured accounts via SSO. Programmatic scripts use approved internal API gateways. Protects corporate data boundaries while maintaining full auditability.

Key PM Workflows

Data and Analytics

  • Querying Live Sources: The agent interfaces directly with product analytics, SQL explorers, and data warehouses via connectors. I pose questions in plain language; the agent writes and executes the queries.
  • Stating Assumptions: Every query result explicitly outlines what was counted, what was excluded, and why (filtering out bot traffic, staff accounts, or skewed date windows).
  • Conservative Framing: Short-term or noisy trends are labeled as "watch" or "inconclusive" rather than premature regressions until substantiated.
  • Canonical Figures: Agreed headline metrics live in persistent agent memory to prevent inflated figures from leaking into executive decks.

Product Strategy and Specs

  • House Templates: The agent maintains awareness of standard product requirement document (PRD) and brief templates, aligning new specs instantly with organizational formatting standards.
  • Socratic Drafting: Rather than writing a spec top-down, the agent builds an outline with targeted questions per section. I answer in rough notes, and it assembles the final draft in my voice.
  • Rapid Prototyping: Building functional internal tools and interactive review pages in hours to test concepts before writing heavy documentation.

Cross-Functional Communication

  • Async Summarization: Processing meeting transcripts and communication threads to extract decisions and action items, filtering out casual chatter to produce clean status updates.
  • Tone and Guardrails: Enforcing communication standards that avoid defensive phrasing, prioritize restating partner perspectives first, and route ad-hoc asks into formal team service desks.

Context Architecture and Prompt Management

Quality outputs stem from structured context layers that persist across sessions, keeping individual prompt requests short and precise:

  1. Standing Rules: Short memory files governing tone, pushback, and safety boundaries with explicit rationales.
  2. Reference Facts: Canonical metrics, template repositories, and data source architectures.
  3. Project Context: Current milestones, open constraints, and absolute dates for active workstreams.
  4. Automated Work Logs: Session summaries automatically maintained by the agent to ensure seamless continuity across working days.

Guardrails and Failure Modes

Failure Mode Enforced Guardrail
Stale task trackers Agent verifies work closure directly from source systems of record.
Inflated metrics Every query explicitly states inclusion/exclusion criteria and requires cross-validation.
Robotic prose Strict Socratic drafting rules: human editorial control, no buzzword inflation, direct phrasing.
Unvetted publishing Automations write strictly to private environments; manual sharing required.
